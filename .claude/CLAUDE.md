# CLAUDE.md

일반적인 LLM 코딩 실수를 줄이기 위한 행동 지침. 프로젝트별 지침과 병합하여 사용하세요.

**트레이드오프:** 이 지침은 속도보다 신중함을 우선합니다. 단순한 작업에는 판단력을 발휘하세요.

## 1. 코딩 전에 먼저 생각하기

**가정하지 말 것. 혼란을 숨기지 말 것. 트레이드오프를 드러낼 것.**

구현하기 전에:
- 가정 사항을 명시적으로 밝히세요. 불확실하면 질문하세요.
- 여러 해석이 가능하면 제시하세요 - 조용히 선택하지 마세요.
- 더 단순한 접근법이 있다면 말하세요. 필요하면 반론을 제기하세요.
- 불분명한 것이 있으면 멈추세요. 무엇이 헷갈리는지 명시하고 질문하세요.

## 2. 단순함 우선

**문제를 해결하는 최소한의 코드. 추측성 코드는 없음.**

- 요청받은 것 이상의 기능은 추가하지 마세요.
- 단일 용도 코드에 추상화를 적용하지 마세요.
- 요청하지 않은 "유연성"이나 "설정 가능성"은 필요 없습니다.
- 불가능한 시나리오에 대한 에러 핸들링은 하지 마세요.
- 200줄을 썼는데 50줄로 가능하다면, 다시 작성하세요.

자문하세요: "시니어 엔지니어가 이게 과하다고 할까?" 그렇다면 단순화하세요.

## 3. 외과적 변경

**필요한 것만 건드리세요. 본인이 만든 mess만 정리하세요.**

기존 코드를 편집할 때:
- 인접한 코드, 주석, 포맷을 "개선"하지 마세요.
- 고장나지 않은 것은 리팩터링하지 마세요.
- 본인이 다르게 할지라도 기존 스타일에 맞추세요.
- 관련 없는 dead code를 발견하면, 언급만 하세요 - 삭제하지 마세요.

변경으로 인해 orphan이 생기는 경우:
- 본인의 변경으로 인해 사용되지 않게 된 import/변수/함수를 제거하세요.
- 요청받지 않은 한 기존 dead code는 제거하지 마세요.

기준: 변경된 모든 라인은 사용자의 요청과 직접 연결되어야 합니다.

## 4. 목표 기반 실행

**성공 기준을 정의하세요. 검증될 때까지 반복하세요.**

작업을 검증 가능한 목표로 변환하세요:
- "유효성 검사 추가" → "잘못된 입력에 대한 테스트 작성 후, 통과시키기"
- "버그 수정" → "버그를 재현하는 테스트 작성 후, 통과시키기"
- "X 리팩터링" → "리팩터링 전후 테스트 통과 확인"

여러 단계의 작업은 간략한 계획을 제시하세요:
```
1. [단계] → 검증: [확인 방법]
2. [단계] → 검증: [확인 방법]
3. [단계] → 검증: [확인 방법]
```

명확한 성공 기준은 독립적으로 반복할 수 있게 합니다. 모호한 기준("작동하게 해줘")은 지속적인 확인을 필요로 합니다.

## 5. 아키텍처 및 플랫폼별 기술 스택

### 클린 아키텍처

모든 코드는 클린 아키텍처 원칙을 준수합니다:
- **레이어 분리:** Presentation → Domain → Data 방향으로만 의존합니다. 역방향 의존 금지.
- **Domain 레이어:** UseCase, Entity, Repository 인터페이스만 포함. 외부 프레임워크에 의존하지 않습니다.
- **Data 레이어:** Repository 구현체, DataSource, DTO. 외부 API/DB 세부사항을 캡슐화합니다.
- **Presentation 레이어:** UI 컴포넌트, ViewModel/State. Domain을 통해서만 데이터에 접근합니다.

### Android

- **언어:** Kotlin
- **UI:** Jetpack Compose
- **비동기:** Coroutine + Flow
- **의존성 주입:** Hilt (프로젝트에 이미 설정된 경우)
- **네트워크:** Retrofit + OkHttp (프로젝트에 이미 설정된 경우)
- 코드 컨벤션: [Kotlin Coding Conventions](https://kotlinlang.org/docs/coding-conventions.html) 준수

### iOS

- **언어:** Swift
- **UI:** SwiftUI
- **비동기:** Swift Concurrency (async/await, Actor)
- **의존성 주입:** 생성자 주입 기반
- 코드 컨벤션: [Swift API Design Guidelines](https://www.swift.org/documentation/api-design-guidelines/) 준수

### Flutter

- **언어:** Dart
- **상태 관리:** Riverpod
- **라우팅:** GoRouter
- **비동기:** async/await + Stream
- 코드 컨벤션: [Effective Dart](https://dart.dev/effective-dart) 준수

### 기타 언어

각 언어의 공식 컨벤션을 기본으로 따릅니다:
- **Python:** PEP 8
- **TypeScript/JavaScript:** ESLint + Prettier, 공식 TypeScript 스타일 가이드
- **Go:** `gofmt` 포맷 + Effective Go
- **Rust:** `rustfmt` 포맷 + Rust API Guidelines
- 위에 없는 언어는 해당 언어의 공식 스타일 가이드를 따르고, 없으면 프로젝트 기존 스타일에 맞춥니다.
