# CLAUDE.md

일반적인 LLM 코딩 실수를 줄이기 위한 행동 지침. 프로젝트별 지침과 병합하여 사용하세요.

**트레이드오프:** 이 지침은 속도보다 신중함을 우선합니다. 단순한 작업에는 판단력을 발휘하세요.

## 1. 코딩 전에 먼저 생각하기

**가정하지 말 것. 혼란을 숨기지 말 것.**

- 불확실하면 조용히 선택하지 말고 가정을 밝히거나 질문하세요.
- 여러 해석이 가능하면 제시하고, 더 단순한 접근법이 있다면 말하세요.

## 2. 단순함 우선

**요청받은 것만. 추측성 코드는 없음.**

- 요청 이상의 기능, 추상화, 불가능한 시나리오의 에러 핸들링은 추가하지 마세요.
- "시니어 엔지니어가 이게 과하다고 할까?" 그렇다면 단순화하세요.

## 3. 외과적 변경

**필요한 것만 건드리세요.**

- 기존 스타일에 맞추고, 고장나지 않은 것은 리팩터링하지 마세요.
- 본인 변경으로 생긴 미사용 import/변수만 제거하세요. 기존 dead code는 손대지 마세요.

## 4. 목표 기반 실행

**성공 기준을 정의하고, 검증될 때까지 반복하세요.**

- 작업을 검증 가능한 목표로 바꾸세요: "버그 수정" → "버그 재현 테스트 작성 후, 통과시키기"
- 여러 단계 작업은 `[단계] → 검증: [방법]` 형식으로 계획을 먼저 제시하세요.

---

## 5. 아키텍처

### 클린 아키텍처

모든 코드는 클린 아키텍처 원칙을 준수합니다:
- **레이어 분리:** Presentation → Domain → Data 방향으로만 의존합니다. 역방향 의존 금지.
- **Domain 레이어:** UseCase, Entity, Repository 인터페이스 포함. 단, 사용자 선택에 따라 인터페이스를 생략하고 Data 레이어 구현체를 직접 사용할 수 있습니다.
- **Data 레이어:** Repository 구현체, DataSource, DTO. 외부 API/DB 세부사항을 캡슐화합니다.
- **Presentation 레이어:** UI 컴포넌트, ViewModel/State. Domain을 통해서만 데이터에 접근합니다.
- **개발 패턴:** 요구사항과 프로젝트 특성에 따라 MVVM, MVI, TCA 등을 사용자에게 제안하고 선택받아 적용합니다.
